# SPHERE v1.34.89 — DEV flat-workspace redesign

**Stage:** GitHub DEV source candidate; server QA, build, actual desktop rendering and DEV public HTTPS cutover **not yet verified**.

## Design intent

Make SPHERE look like a production SAP Basis investigation cockpit, not an AI-generated collection of cards. Use hierarchy, whitespace, restrained separators, SAP-native metric language and aligned tables. Keep the proven component tree and API evidence.

## Implementation inventory

| Feature | DEV source treatment | Preserved behaviour |
| --- | --- | --- |
| Header/source/health | restrained status strip | Rundeck/Manual selection, PDF Preview, independently reported system health, collector, SAP-data freshness |
| APP1–APP5 | softer standalone host surfaces | SAP status distinct from Infrastructure, CPU/RAM/WP, source timestamps, selected host |
| CPU/RAM/Technical Trends | flatter plot region and shared controls | per-APP traces, Peak/Avg semantics, bucket/sample time and thresholds |
| Operational Analysis | **one flat 6-action toolbar**, no three nested cards | Correlated Events, Observation History, SAP Issues, SAP Availability, Infrastructure and System Data |
| Jobs & Programs | emphasis on table reading, Live/Review/Search | actual observed vs loaded counts, selected-row context, searchable retained source |
| Job / Program Analysis | low-noise metric and WP layout; related routes flat | independent CPU multicore/PSS/IO/WP values, SM37 authority, modal Back context |
| Infrastructure Analysis | compact host picker, history and current snapshot | 5 APP IDs, filesystem, network, storage, distinct Infrastructure freshness, `/SAP_ARCH` provenance |
| SAP Checks | simple indicator/availability evidence surfaces | alert states, no invented availability or false SAP-down inference |
| Events & History | timeline plus supporting tables, without second dashboard | correlation timing without causal verdict, observation run drilldown |
| System Data | neutral collection/service/token surfaces | Reader and Runner are report-only; token rotation stays locked |
| PDF | quieter existing preview modal | existing generated bytes, download and external preview links |

## Flow contract

- APP -> APP Analysis -> Job -> Back APP -> Back cockpit.
- Trend datapoint -> Trend Details, preserve metric, host, timestamp.
- Live Job -> Job Analysis -> related History / Infra / SAP Checks / Events -> Back same Job.
- Review or Search -> Quick Analysis -> save Review / Open Performance Analysis -> correct Back.
- Action toolbar -> six existing destinations with one click each. Observation History remains disabled until a Job identity exists.
- System Data -> Collection History, SPHERE Services, Token Management (read-only reporting).
- PDF Preview -> current report file; no new synthetic report content.

## Technical approach and testing

No new framework or graph library. Reuse React, Vite, ECharts, existing CSS tokens and actual REST API data. Only change frontend files, tests and documentation on branch `rundeck-sphere-dev`. No backend, DB schema, Nginx, SAP, Rundeck credentials, threshold, or PROD changes.

Source/code review must be followed by one SHA-locked `ops/rundeck/release-ui-dev.sh <sha>` server run. It checks read-only Alembic version `20260929_0007`, source, QA/build, desktop Playwright (1366/1536), public DEV HTTPS parity and DEV symlink rollback. There is no claim of release PASS before server proof.

Images/mockups are **design references only**: illustrative values, new graphs or actions not provided by the API must never be silently fabricated. Full responsive, accessibility and 1920px coverage must be checked before any future PROD promotion.

## Known delivery boundary

This release flattens the existing UI and connected interactions; it **does not add any backend-fed graph/metric** depicted only in concept art. Visual geometry and screenshot inspection still require a real preview.
